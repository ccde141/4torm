# 故障检修

这里按现象整理常见的启动、模型请求和会话问题。先确认提供商地址、模型名称和当前 Agent 配置，再按对应条目处理。

## LM Studio 报 assistant 消息为空

如果 LM Studio 返回类似「assistant message must not be empty」或「No user query found in messages」，通常是当前会话历史里存在空的 assistant 占位消息，而模型使用的提示模板不接受这种写法。

处理方式：

1. 在「提供商管理」中找到当前模型
2. 将该模型的配置切换为「LM Studio」
3. 重新发送本轮消息

这个配置只整理发给 LM Studio 的请求，不会修改会话原文，也不会影响同一提供商下的其他模型。LM Studio 使用随机端口或经过代理时，不能仅靠地址自动判断，因此需要手动选择。

## 模型请求返回 400

先检查：

- API 地址是否包含正确的接口前缀
- 模型名称是否与服务端实际名称一致
- 当前协议是否为 OpenAI Compatible 或 Anthropic Messages
- 自定义请求头是否为合法 JSON
- 当前模型是否选择了不适用的 profile

如果错误只在切换模型后出现，先重新发送一次；4torm 会按当前目标模型重新整理会话历史，不会沿用上一个模型的请求格式。

## 图片发送失败

图片检测只验证当前接口是否接受测试图片，不代表模型一定能稳定理解所有图片。

检查：

- 当前模型是否完成图片理解检测
- 图片格式和大小是否在服务商限制内
- 当前协议和代理是否允许图片输入
- 模型本身是否为视觉模型

## 文档页面没有打开

正常安装会在根目录执行依赖安装后的文档构建。若服务端提示没有发现文档构建产物，在项目根目录执行：

```bash
npm run docs:build
```

然后重新启动服务。

## 仍然无法判断问题

保留完整错误信息、使用的模型、提供商协议和触发步骤。不要只根据「探测失败」判断模型不支持某项能力；网络错误、鉴权失败、代理限制和服务端临时错误都可能产生相同表象。
