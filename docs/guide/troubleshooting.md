# 故障排查

遇到错误时，先看界面上的完整提示，再看 HTTP 状态码。4torm 会把部分模型服务错误转换成框架错误：例如界面或接口显示 `502`，提示正文却注明上游 `HTTP 503`。这时应按正文中的上游原因检查模型服务，不能只根据外层状态码判断。

## 先确认故障发生在哪一段

- **界面无法连接 4torm**：确认后端已经启动；浏览器生产模式还要检查本机 HTTPS 证书是否被浏览器信任。
- **能打开界面，但模型请求失败**：检查提供商类型、API 地址、密钥、准确模型 ID，以及模型级参数。获取模型列表成功，不代表正式对话所需的请求参数也能被接受。
- **某个文件或附件操作失败**：阅读该操作的错误提示，核对文件格式、大小，以及 Agent 的执行权限。

## 更新后出现接口不存在

如果新界面提示 `Route ... not found`，先确认客户端连接的是哪一个后端，以及那个后端是否已经更新。仅刷新网页不会更新仍在运行的旧后端。源码开发模式的 `tsx watch` 会在服务端源码变化后重启；使用生产服务时，需要停止旧进程，再按更新后的版本重新启动。服务重启后刷新客户端。

远程 Electron 加载的是后端提供的网页，更新与构建应在后端那份源码中进行。部署与地址配置见[独立后端与远程客户端](https://github.com/ccde141/4torm/blob/master/REMOTE.md)。

## 按错误提示继续检查

| 状态或提示 | 常见原因 | 可以先做什么 |
|---|---|---|
| `400`、`422` | 模型不接受请求内容或参数；必要字段缺失 | 核对提供商类型、模型 ID 和模型级配置，查看错误正文 |
| `401`、`403` | 密钥错误、账号或模型无权限；`403` 也可能是文件路径被拒绝 | 区分错误来自模型服务还是本地工具，再检查对应权限 |
| `404` | 地址、模型或要操作的对象不存在 | 核对 API 地址、模型 ID 和当前对象 |
| `409` | 操作与当前状态冲突，例如任务仍在运行 | 查看当前执行或待处理状态，结束后再操作 |
| `413`、`415` | 文件过大，或媒体类型不受支持 | 检查文件大小、格式和接口限制 |
| `429` | 模型服务限流、并发或额度不足 | 查看服务商配额与并发限制 |
| `500` | 4torm 内部处理或存储出错 | 保留错误提示，查看后端日志 |
| `502`、`503`、`504` | 上游无法连接、暂时不可用或超时；也可能是框架映射后的状态 | 同时查看提示中的上游状态，确认服务、地址、网络与负载 |
