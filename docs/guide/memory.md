# 记忆与召回

记忆用于保留值得再次使用的信息，召回则帮助 Agent 在当前任务中找回相关内容。

你可以为 Agent 保存偏好、项目约定、已确认事实和经验，也可以让它检索以前整理过的工作记录。目前，两级自动召回用于季风会话。

## 记忆与会话记录的区别

| 内容 | 保存什么 | 适合什么时候使用 |
|---|---|---|
| **Agent 长期记忆** | 偏好、约定、经验和资料线索 | 希望同一个 Agent 在不同会话中继续参考这些信息 |
| **会话历史** | 人类消息、Agent 回复和工具执行记录 | 回看当时的交流与操作 |
| **压缩工作记录** | 会话压缩时整理出的背景、进展、决定和待办 | 找回以前做过什么、工作推进到了哪里 |
| **气旋工位记忆** | 当前项目中的岗位经验、事实和资料索引 | 让一个工位持续积累本项目的工作知识 |

长期记忆属于对应 Agent，不同 Agent 分别保存。气旋工位记忆属于工位，更换绑定的 Agent 后仍会保留。

## 保存和管理记忆

在「控制台」打开 Agent 卡片，进入「记忆」，可以新增、编辑或删除条目。

记忆分为四类：

- **偏好／纠正**：你希望 Agent 遵循的表达习惯、工作方式或修正意见。
- **事实**：已经确认、以后仍可能使用的信息。
- **踩坑**：遇到过的问题、发生条件和有效处理方法。
- **资源**：值得再次查找的文档、文件位置和其他资料线索。

也可以在会话中直接交代：

> 记住：这个项目的界面文案使用中文，保留必要的英文技术术语。这项约定只适用于当前项目。

Agent 可以使用记忆工具保存内容。保存后，你可以在它的「记忆」页面检查和调整。

一条记忆最好围绕一个主题，写清适用项目、条件和结论。例如，“订单页每页显示 24 条”比“以后都用 24 条”更容易被正确使用。

## 三种召回方式

### 一级：检索匹配

一级召回根据当前发言，检索相关记忆和工作记录。

不配置向量模型时，可以使用关键词检索。配置向量模型后，还可以通过含义相近的表达寻找资料，例如用“界面文字用什么语言”匹配此前保存的“项目文案使用中文”。

这一层不需要额外的对话模型参与筛选。

### 二级：模型精选

二级召回使用单独选择的语言模型，结合当前发言和近期对话，搜索、阅读并筛选相关资料。

它可以继续搜索候选之外的内容，也可以在没有合适资料时不选取条目。筛选出的内容作为历史参考交给当前会话的主 Agent，正式回复仍由主 Agent 完成。

二级可以独立开启，不要求先配置向量模型。

### 主动查询

Agent 也可以根据任务需要，主动使用工具搜索记忆、读取条目或查看工作记录原文。

你可以明确提出：

> 先查一下我们以前对这个项目的约定，再继续修改。

关闭一级或二级自动召回，不影响 Agent 主动查询记忆。

## 配置记忆召回

打开「设置 → 记忆召回」，分别配置一级检索和二级模型精选。

### 一级检索

开启「一级召回 · 检索匹配」后，可以选择：

- **关键词检索**：无需嵌入模型。
- **向量检索模型**：选择支持嵌入接口的 Embedding 模型，再点击「验证嵌入」。

Embedding 模型负责把文字转换为便于比较相关性的向量，不负责生成对话回复。普通对话模型应放在二级模型精选的位置；向量检索需要模型服务实际提供嵌入接口。

嵌入模型可以部署在本机，也可以使用云端服务。先在模型提供商中配置连接和模型，再回到这里选择。

建立索引、处理更新和查询时会使用嵌入模型，已有记录的向量会复用。本地部署主要使用本机计算资源；云端调用按供应商规则计费。

### 二级模型精选

开启「二级召回 · 模型精选」，选择「中层召回模型」，点击「验证模型」检查连接与示例筛选。

召回模型可以与主会话使用不同的模型。希望降低等待时间时，可以选择响应较快的云端模型或轻量 Instruct 模型；使用本地模型时，结合硬件和实际响应速度选择。

模型精选会产生额外的模型调用；选中的参考内容进入主会话后，也会占用上下文。

两级召回可以分别开关。修改后点击「保存」生效，关闭时会保留已经选择的模型。

## 选择召回时机

「召回时机」控制二级模型精选的执行时间。

| 方式 | 实际过程 | 适合的使用方式 |
|---|---|---|
| **发送前召回** | 先完成记忆精选，再让主 Agent 处理本次消息 | 希望当前回答就能参考找回的资料 |
| **发送后召回** | 主 Agent 处理本次消息时，后台准备相关资料；后续发言时再根据相关性带入 | 希望当前回复尽快开始，或召回模型响应较慢 |

发送前召回时，界面会显示「Agent 回忆中」，随后进入正常回复过程。

一级检索仍根据当前发言匹配资料，不需要等待后台二级精选完成。

## 查看本次使用的记忆

自动召回的资料会在对应的人类消息上方显示为「本次回忆」或「相关记忆」。两种名称表示同一种记录。

展开后，可以查看：

- 引用的记忆或工作记录；
- 本次带入的内容；
- 来自一级检索还是二级模型精选；
- 相关项目、日期及工作记录的压缩序号等来源信息。

这里展示的是已经带入本次会话的参考。后台找到的候选资料，需要经过筛选并实际加入会话后，才会出现在这里。

已经存在于当前上下文中的同一份参考，会避免重复追加。因此，每次发言不一定都会出现新的记忆条目。

## 压缩后的工作如何接续

会话压缩会整理背景、约定、进展和剩余步骤，供当前任务继续执行。成功保存的压缩摘要也可以作为工作记录被检索，并保留日期、当日压缩序号和所属会话。

例如，你可以在同一个 Agent 的另一段季风会话中说：

> 继续上周整理资料的工作。先找之前的工作记录，确认已经完成的部分和剩余事项。

Agent 可以先读取相关摘要，需要核对细节时，再查阅对应的原始记录。

压缩工作记录与长期记忆分别保存。项目经历可以留在工作记录中；值得以后反复使用的方法、偏好和约定，再单独保存为长期记忆。

## 更新和删除资料

记忆发生变化时，可以直接在 Agent 的「记忆」页面修改。新的召回会核对来源，并使用当前有效的内容。

编辑会话或压缩摘要后，相关工作记录会按更新后的内容重新整理；删除来源会话后，对应工作记录不再参与后续召回。

这些操作影响后续检索与引用，过去已经生成的回复仍保留在原会话中。新的任务要求可以直接在当前会话中说明，例如：

> 之前每页 24 条的约定已经变更，这次改为 30 条，并更新对应记忆。
