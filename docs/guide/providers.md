# 模型提供商

在控制台的「提供商管理」中，先选择与你实际使用的模型服务相符的提供商类型，再填写 API 地址和密钥。这个类型决定 4torm 怎样组织请求；只改地址或模型名称，不能代替选择正确的类型。

支持前后端跨系统使用，例如在 Linux 上运行后端，在 Windows 上使用网页或桌面端；模型服务由后端连接。部署方法见[独立后端与远程客户端](https://github.com/ccde141/4torm/blob/master/REMOTE.md)。

## 添加模型

点击「添加提供商」选择预设。预设包括 OpenAI Compatible、DeepSeek、Kimi、Alibaba Cloud Model Studio、Zhipu AI、MiniMax，以及 LM Studio、llama.cpp、Ollama、vLLM 等本地推理服务。创建后可以修改名称、地址和密钥；不需要密钥的本地服务可留空。

![提供商配置与尚未检测的示例模型](/images/guide/provider-current.png)

点击「获取模型列表」，选择要在 4torm 中使用的模型。若服务没有提供完整列表，也可以按服务给出的准确模型 ID 手动添加。

模型列表、能力检测、对话和压缩均由后端请求。API 地址中的 `127.0.0.1` 指向后端所在的电脑或容器；在 Windows 客户端连接 Linux 后端时，应填写 Linux 后端能访问的模型地址。模型列表接口返回 `404` 时，可先核对服务是否支持列举模型，不必把它等同于对话接口不可用。

## 配置与检测

先保持提供商参数和模型级配置的默认值。只有当所用服务或模型明确要求某项参数时，再单独调整它；如果列表能获取、能力检测能通过，但正式对话失败，也要检查模型级参数是否被设成了服务不接受的组合。

DeepSeek 专属类型的默认最大输出为 **8,192 tokens**，允许设置的上限为 **393,216 tokens**。上下文容量与单次输出上限是两项限制，不应把百万级上下文容量填入最大输出。

模型行提供工具调用与「图片理解」检测。检测用于确认当前接口能否接受一次对应的测试请求，不能保证模型在所有任务中的效果。图片检测通过后，可以在季风会话中向该模型发送图片；检测失败时，也应结合返回错误判断是能力限制、鉴权还是连接问题。
