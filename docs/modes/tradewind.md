# 信风 · 工作流

信风把一项工作拆成有先后关系的节点，并把每一步的结果交给下一步。适合那些需要多名 Agent 接力、固定检查关口，或希望以后按同一结构再次运行的工作。

例如，准备一份发布方案：入口写明目标；资料 Agent 整理事实；文案 Agent 根据整理结果写方案；暂停点留给你检查；出口收集最终结果。运行时，你能看到工作走到了哪个节点，并在需要介入时打开相应内容。

## 搭建一条工作流

从左侧节点栏把节点拖到画布，再用连线安排交接顺序。点击节点可以在右侧设置它的职责和内容。你也可以在季风中描述目标、分工和需要人工检查的位置，让 Agent 帮你创建或修改信风工作流；创建后仍可以回到画布调整。

![代码审计工作流中的并行节点与合并出口](/images/tradewind/workflow-canvas.webp)

常用节点各司其职：**入口**给出初始任务；**Agent** 绑定一名已有 Agent 执行工作；**暂停点**等你检查后再放行；**出口**收集结果。需要多人讨论时，可以放入**会议室**；想给某个 Agent 留下持续指引，可以用 **Note**。Note 只提供提示，不会作为一个执行步骤运行。

节点完成后，会沿普通连线把整理好的交接内容送往下游。这个交接内容称为“信封”：它告诉下一个节点已有结果和接下来要做什么，并非把上一个节点的完整对话搬过去。如果一个节点同时依赖几条上游分支，它会等这些分支的信封都到达后再开始。各节点也可以使用同一工作流的共享文件。

## 选择运行方式

**手动运行**适合边执行边参与。工作从入口开始；你可以打开 Agent 节点查看过程，进入会议室讨论，或在暂停点检查并修改即将交给下游的内容。会议室结束后，会先由会议助理整理纪要，再把纪要作为信封向后交接。

**自动运行**适合无需中途人工介入的流程。可以只运行一圈，也可以建立循环档案，设置运行圈数、圈间等待，以及上一圈的结果如何进入下一圈。自动运行不能包含会议室或暂停点。

无论选择哪种方式，启动前都会保存并检查当前画布；配置或连接有问题时，界面会指出问题，工作流不会开始。

## 让 Agent 推进工作流

你可以在季风中说明任务目标、节点分工和交接要求，让 Agent 创建或调整信风工作流，并启动执行。已有工作流也可以由它读取后继续使用。

运行后，Agent 可以查看进度、读取节点会话和会议记录，向 Agent 节点补充要求。遇到会议节点，可以参与讨论、与会议助理私聊，调整已配置成员的参会安排和发言顺序，并结束会议，让纪要继续传给下游。暂停点由你在信风页面检查和放行。

例如：

> 帮我建立一条使用指南审阅工作流：资料检查与表达检查两路并行，再由汇总节点整理修改建议，最后输出清单。搭建好后启动自动运行，跟进各节点的结果，完成后把清单交给我。

打开对应的信风工作流，可以在画布和进度面板查看这次运行，也可以进入节点查看具体过程。

## 看见执行与结果

运行时，画布和「工作流 · 进度」会显示各节点的状态与信封交接。点击 Agent 节点可以查看它的会话、工具活动和当前处理内容；点击暂停点可以确认或修改信封，再让这一支继续。出口收到一条结果时不会立刻结束，仍会等待本次所有应到达的信封完成交接。

顶部的「停止工作流」会结束整次运行，尚未完成的内容不会继续传给下游。已经完成的节点产出和本次运行记录仍会保留，供你回看。工作流定义与共享文件会继续保留，之后可以再次运行。

## 整理对话记录

Agent 节点、会议公共输入框和会议助理私聊都支持 `/compact`，用于整理当前对话。会议公共输入框还支持 `/reset`，归档并清空本会议的公共讨论与会议助理私聊。
