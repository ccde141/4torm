# 信风 · 工作流编排

信风把一项工作拆成节点，让 Agent 按你安排的连接关系交接。既可以按固定依赖推进，也可以由 Agent 根据结果选择下一步，或退回某个节点修改。适合多名 Agent 接力、设置检查关口，以及按同一结构重复运行的工作。

例如，准备一份发布方案：入口写明目标；资料 Agent 整理事实；文案 Agent 根据整理结果写方案；暂停点留给你检查；出口收集最终结果。运行时，你能看到工作走到了哪个节点，并在需要介入时打开相应内容。

## 搭建一条工作流

左侧工作流列表按「严格依赖」和「条件交接」分开。先选择流转方式，再新建工作流。选中工作流后，可以在「编排」「运行」「运行记录」之间切换；列表旁的问号可以随时查看两种方式的区别。

在「编排」中，从节点栏把节点拖到画布，再用连线安排交接关系。点击节点可以在右侧设置它的职责和内容。你也可以在季风中描述目标、分工和需要人工检查的位置，让 Agent 帮你创建或修改信风工作流；创建后仍可以回到画布调整。

新建的工作流先显示为「本地草稿」，保存成功后成为已保存的工作流。空画布也可以保存，是否能运行由启动前的图校验决定。「打开工作区」会先保存当前草稿，再创建并打开该工作流的共享文件目录。

常用节点各司其职：**入口**给出初始任务；**Agent** 绑定一名已有 Agent 执行工作；**暂停点**等你检查后再放行；**出口**收集结果。严格依赖工作流还可以放入**会议室**。想给某个 Agent 留下持续指引，可以用 **Note**；它只提供提示，不会作为一个执行步骤运行。

节点之间传递的交接内容称为“信封”：它告诉下一个节点已有结果和接下来要做什么，并非把上一个节点的完整对话搬过去。各节点也可以使用同一工作流的共享文件。

## 选择流转方式

每张工作流图采用一种流转方式，至少有一个入口，并共用一个出口。两种方式的工作流分别保存和编排，可以同时运行。

**严格依赖**按预设分工推进，交接连线不能形成循环。如果一个节点依赖几条上游分支，它会等这些分支的信封都到达后再开始。适合「资料检查与表达检查分别完成，再汇总交付」这样的固定流程。

**条件交接**让节点根据结果，从已经连接的目标中选择一个交接。比如「制作 → 审查」，通过后交给出口，未通过则退回制作。每个入口产生一封带独立 ID 的信封，一个节点一次处理一封信封；其他信封按实际到达顺序排队。每次交接都沿用原信封，不会分裂成多份。完成正式交接后，该节点对这封信封的本轮处理即结束，不能再把同一封信封发送给另一个对象。条件交接不支持会议室节点。

条件交接允许返工连线，但每个执行节点都必须能从入口到达，并存在通向出口的路线；入口和暂停点各自只能连接一个后续交接对象。把节点连成一个没有出口路线的封闭循环，不能通过图校验。

两种方式中的 Agent 都可以相互联络，询问或补充必要信息；联络不会代替正式信封交接。人类消息或 Agent 联络本身不会产生新的正式信封。

## 选择运行方式

流转方式决定如何交接，运行方式决定是否需要你中途参与。两种流转方式都可以选择以下运行方式：

**交互运行**适合边执行边参与。工作从入口自动推进；你可以打开 Agent 节点交流，或在暂停点检查并修改即将交给下游的内容。严格依赖中的会议室结束后，会先由会议助理整理纪要，再把纪要作为信封向后交接。

**无人值守**适合无需中途人工介入的流程，不能包含会议室或暂停点。可以只运行一圈，也可以建立循环档案，设置运行圈数、圈间等待，以及上一圈的结果如何进入下一圈。条件交接中的返工仍属于同一次运行；循环运行则是在本次完成后，重新从入口开始。

无论选择哪种方式，启动前都会检查当前画布，通过后保存并启动；配置或连接有问题时，界面会指出问题，工作流不会开始。严格依赖的无人值守运行还要求各 Agent 节点使用支持原生工具调用的模型。

启动后会切换到「运行」，显示本次启动时的图。之后查看或编辑「编排」中的草稿，不会替换这次运行使用的图。

## 让 Agent 推进工作流

你可以在季风中说明任务目标、节点分工和交接要求，让 Agent 创建或调整信风工作流，并启动执行。已有工作流也可以由它读取后继续使用。

调整已有流程前，Agent 会读取完整编排；大型图可以按同一版本继续分段读取，避免只凭列表摘要修改而丢失节点职责。保存仍会核对版本，内容已变化时需要重新读取。没有调整的节点布局、尺寸、备注及连线信息会保留。

运行后，Agent 可以查看进度、读取节点会话和运行记录，向 Agent 节点补充要求。发往节点的消息返回「已接收」表示已进入队列，仍需查看节点回复或执行状态确认处理结果。严格依赖中的会议节点还可以由它参与讨论、与会议助理私聊，调整已配置成员的参会安排和发言顺序，并结束会议，让纪要继续传给下游。暂停点由你在信风页面检查和放行。

按你的要求，季风还可以停止指定工作流的本次执行，或暂停、恢复指定节点的处理轮次。恢复会重新执行被暂停的轮次，已经完成的工具副作用不会回滚；普通发话轮可以单独中止，持有正式信封的轮次需暂停处理或停止整次工作流。控制请求会核对执行、节点和轮次身份，接收请求后仍需跟进真实收尾状态。人工暂停点继续由你检查和放行。

启用相应的信风能力操作后，Agent 也可以读取循环档案，修改或新增单个档案，再按你的要求启动。修改工作流或单个循环档案时，都需要核对已读取的版本；发生冲突后，应重新读取再修改，避免覆盖你同时做出的调整。保存配置本身不会启动工作流。当前循环使用每圈结束后的相对等待间隔。

需要核查旧任务时，可以让 Agent 按工作流查找某次运行，再读取结果、交接事件和归档会话。较长的事件列表和正文可以继续分页读取；正文续读会核对内容版本，内容变化时需重新读取，不必依靠当前仍打开的节点会话。

例如：

> 帮我建立一条严格依赖的使用指南审阅工作流：资料检查与表达检查两路并行，再由汇总节点整理修改建议，最后输出清单。搭建好后启动无人值守运行，跟进各节点的结果，完成后把清单交给我。

需要审查后返工时，可以这样交代：

> 建立一条条件交接工作流：制作节点编写产品介绍页，审查节点检查页面内容和窄屏布局。审查通过后交给出口；未通过时，只能沿预设连线退回制作节点，并附上具体问题。设置好各节点职责和连接关系后，启动无人值守运行，最后交付页面文件和审查结论。

需要自己确认中间结果时，可以这样交代：

> 建立一条严格依赖工作流：资料节点整理三份产品说明，文案节点据此起草介绍，在出口前加一个暂停点。启动交互运行，走到暂停点后由我检查和放行，再交付最终稿。

需要重复执行并回查结果时，可以这样交代：

> 读取已有的检查工作流，保留其他循环档案，新增一个运行两圈、每圈结束后等待一分钟的档案，然后启动。完成后分别列出两圈的交付，并从运行记录中核对信封交接与检查节点的工具结果。

## 看见执行与结果

左侧工作流卡片用颜色提示最近一次运行：**蓝色**表示运行或等待，**黄色**表示需要介入，**红色**表示失败或异常结束，**绿色**表示已完成且尚未查看。点击已完成的卡片会消去本次完成的绿色提示，运行记录仍会保留；开始新一次运行后，卡片会跟随新的状态变化。

在「运行」中，可以查看节点状态、正在处理的信封、等待队列和近期交接。Agent 节点上的会话按钮可以直接打开会话，查看工具活动和当前处理内容；点击等待检查的暂停点，可以确认或修改信封，再让这一支继续。已结束运行的会话按钮打开对应的归档记录。不同工作流可以同时执行，包括不同的流转方式；通过「活跃工作流」切换查看，不会停止其他工作流。

![运行图显示已完成与执行中的节点、信封进度和直接进入会话的按钮](/images/tradewind/workflow-running.png)

「运行记录」按次保存运行图、起止时间与状态，并按「交付结果」「节点上下文」「会议记录」「信封交接」「全部事件」查看内容。事件可以按时间和类型筛选，查看信封从谁发出、何时发送和接收，以及相关的执行过程；也可以从记录打开当次运行图。

节点和会议归档展示输入消息、Agent 回复与工具内容，不展示系统提示词和内部思考。较长的正文和事件列表可以继续翻页。运行中的部分归档可能尚未保存；没有保存的旧记录会明确显示缺失，不会用当前会话代替。

![按次查看运行记录，在节点上下文中回看输入、工具调用与交付回复](/images/tradewind/run-history.png)

严格依赖会等待应到达的分支完成交接；条件交接会等待本次各入口的信封分别交付，因此某一封到达出口不一定代表整次运行已经完成。

「停止工作流」会结束当前工作流的这次运行，尚未完成的内容不会继续传给下游。已经完成的节点产出和运行记录仍会保留，工作流定义与共享文件也会继续保留，之后可以再次运行。

删除工作流则会移除它的定义、共享工作区和运行记录，无法从列表恢复。需要保留成果时，先另行备份文件。

## 整理对话记录

Agent 节点、会议公共输入框和会议助理私聊都支持 `/compact`，用于整理当前对话。会议公共输入框还支持 `/reset`，归档并清空本会议的公共讨论与会议助理私聊。
