# 气旋 · 团队协作室

气旋是一处可以长期使用的多人工作场所。你可以为一个项目建立工作室，让不同 Agent 分别坐在自己的工位上工作；需要一起商量时，再把相关工位请进群聊。所有人共用工作室文件，但每个工位的私聊和每场群聊的讨论分别保存。

例如，准备一次产品发布时，你可以设立「文案」和「检查」两个工位：先分别交代工作，再让它们在群聊中讨论发布内容。文案工位写出的文件，检查工位可以在同一工作室继续检查；两边此前与你的私聊不会自动公开给群聊。

## 从工作台了解项目

打开工作室后，「工作台」汇总各工位的状态、执行记录、工位记忆和最近事项。可以按状态筛选，或搜索工位名称、职责和绑定的 Agent。统计对应当前工作室中的工作，不会合并同一个 Agent 在其他地方的活动。

点击工位卡片，可以查看「工位概览」「履历」「工位统计」「配置与提示词」「工位记忆」「继承能力」和「工作室协作」。履历支持按「工作活动」或「岗位变更」筛选、加载更早记录，并可打开相关会话、配置或记忆。

## 让工位开始工作

点击工作室列表中的加号创建工作室，再添加工位。每个工位选择一名已有 Agent，并设置工位名称；角色提示词用于说明它在这里承担的职责。工位还可以有一张简短的职责名片，供其他工位决定向谁询问或派工。

从「文案」工位打开私聊，就可以像平常一样交代任务、查看工具执行和任务板。「检查」工位有另一段独立私聊。它们都能使用工作室共享文件。工位绑定的 Agent 日后可以更换，已有的工位私聊和工位记忆会继续保留。

在「配置与提示词」中，可以调整工位名称、绑定的 Agent、岗位职责和工位提示词。工位提示词默认与 Agent 的默认角色一起使用，也可以选择用它替代默认角色。「继承能力」展示绑定 Agent 提供的模型、工具和技能；这些基础能力仍在控制台配置。

工位记忆用于保存这个项目中的岗位经验、已确认事实和资料索引，你和工位 Agent 都可以补充。工位私聊、联络和群聊中的该工位共用这份岗位记忆，记忆正文按需读取。适合跨项目使用的经验则属于池中 Agent 的长期记忆。例如，文案工位记住本项目的用词约定，绑定 Agent 的通用写作方法仍可在其他工作场所使用。

工作室的公告板适合写所有工位都需要知道的目标和约定，例如发布范围或统一的交付标准。它与某个工位的私聊不同，是工作室共同的信息。

## 让工位相互协作

在「协作结构」画布上，把可以直接协作的工位放进同一组；不同组之间也可以画联络线。保存后，工位才会按这些关系发现彼此。画布决定的是**谁能主动联络谁**，不会自动启动任务或合并对话。

每个工位的「工作室协作」还可以分别启用工位联络、任务派发和工作室公告工具。这里管理的是当前工位在本工作室中的协作能力；可联络对象仍由协作结构决定。

![当前协作结构中的工位、协作组与组间联络线](/images/cyclone/collaboration-structure-current.png)

*示例结构：内容制作组内有两个工位，内容设计与交付检查组之间设置双向联络。*

如果文案工位只需要向检查工位确认一条要求，可以用 `contact` 发问，等到答复后继续当前工作。如果一整份文案需要独立检查，可以用 `dispatch` 派给检查工位；文案工位不用一直等待，之后再查看派工的状态和结果。检查工作会发生在检查工位自己的会话中，不会把双方私聊拼成一段记录。

联络最多等待 30 秒接入。对方一直忙碌、未接入时，本次请求会撤回，返回忙线，之后不会补送，也不会写入对方会话；发起方可以先做其他工作，稍后再联系。已接入后若又等待 30 秒仍未回复，则返回「仍在执行」和联络编号，对方继续处理，可通过 `contact_read` 查询原请求。派发会立即返回登记回执；目标在接入期限 30 秒内未接入时同样撤回。**登记成功、已经接收和执行完成是不同状态，已送达的事项应查原记录，避免重复交办。**

工位也可以查询自己的近期事项与派发状态。派发后，它可以先完成手头工作，收尾时再核对回报，并在回复末尾说明仍未完成的事项；必要时主动联络对方确认。派发结果会在源工位下一次私聊或继续执行时带入，不会仅因结果到达就自动开始新一轮工作。

工位的记忆、履历和派发查询会自动使用当前工作室与工位身份；联络、派发也只面向协作结构允许的对象。工位不需要自行填写所属项目或来源身份。

例如，在文案工位的私聊中交代：

> 请把工作室里的发布稿交给检查工位，核对产品名称、数据来源和遗漏的使用限制。你继续整理配图说明，等检查结果回来后，再结合意见修改发布稿。

使用前，需要让两个工位在协作结构中可以联络，并启用文案工位的任务派发能力。

## 把讨论放到群聊

需要共同讨论时，创建群聊并邀请相关工位。它们会按会议设置中的顺序，在你发言后依次回应。邀请时可以选择让工位先作自我介绍、公开一段工作摘要，或静默加入；这不会把工位的完整私聊带进会议。

群聊右上角的「会议设置」可以调整话题、发言顺序和参与工位。「请离会议」只会让工位离开当前群聊，它的工位、私聊和已有发言仍会保留。

群聊的 `build` 模式适合边讨论边使用工具处理工作室文件；`plan` 模式适合先讨论方案，限制直接写文件、删除文件和执行命令。参与者在两种模式下都可以按协作关系联络其他工位。

你还可以为工作室设置一名会议助理，在群聊右侧单独与它交流。它能参考当前群聊和公告板，提供分析、建议与整理，不调用执行工具或给工位派工。私聊内容不会进入公共讨论；每场群聊保留各自的会议助理私聊。

## 设置工作室主管

工作室主管负责整个项目的统筹，与群聊中的会议助理分别配置。主管独立于工位和协作组，使用一段持续会话，可以查看项目进展、管理工位和协作结构、派发任务，并根据工位回报跟进交付。它使用工作室公共工作区，有自己的任务板和项目记忆；项目管理与协作工具自动绑定这个工作室。

需要主管时，在新建工作室时选择一名已有 Agent，也可以之后打开左侧「工作室主管」，点击「配置」。同一名池化 Agent 可以承担主管和会议助理，但两者的会话和职责分别保存。每个工作室只有一段主管会话，切换工作室会切换对应主管的记录。

![工作室主管的 Agent 绑定、主管提示词与持续会话](/images/cyclone/workshop-supervisor.png)

*示例配置与对话：主管独立于工位，集中汇总交付和待核实事项。图中内容均为示例数据。*

主管可以创建、调整和移出工位，修改协作关系、公告板与群聊设置，查询工位记忆和履历，以及管理项目内会话。移出工位时会保留原有会话、任务板、记忆和附件快照；正在工作的工位不能直接移出。

选择主管并不会自动开始工作。先向它交代项目目标；之后，工位可以用 `supervisor_message` 报告进展、阻塞或协调请求，主管也会接收自己派发任务的回执，继续核对未完成事项。工位可以给主管发信息，不能给主管派活；信息送达也不表示主管已经查看或处理。主管等待你回答问题或被暂停后，需要你处理才能接续。

## 让 Agent 统筹工作室

在季风中，你可以让 Agent 建立气旋工作室、添加工位和群聊，为各工位交办任务，再根据回报继续安排工作。已有工作室也可以直接接续。

独立调查、编写文件和多步骤执行，优先分别交给工位私聊。群聊用于同步背景、讨论分歧和汇总简报；公告板保存共同目标、约定和结论。简单问答或共同讨论可以直接在群聊完成。

负责统筹的 Agent 可以先查看工作室或单个工位的概况与近期事项，按需读取工位记忆，再结合工位回复和派工结果接续任务。它也可以调整群聊成员，并与会议助理单独交流。

启用相应的气旋能力操作后，季风 Agent 还可以在建组时明确选择主管（`supervisorAgentId`），或用 `configure_collaboration_supervisor` 为尚未配置主管的工作室首次绑定；会议助理使用另一项 `chairAgentId`，选择会议助理不会同时配置主管。Agent 可以通过 `start_collaboration_supervisor_chat` 向主管转达你的项目目标，用 `read_collaboration_supervisor` 查看状态与收件情况，再回读主管会话和工位交付。这些交办保留委托 Agent 的来源；更换已有主管由你在「工作室主管」的配置中完成。

外部统筹 Agent 每次调用都需要指定目标工作室，读取工位资料时还要指定工位。它可以读取岗位配置、继承能力、记忆和履历，不能通过这些读取入口修改岗位或跨工位写记忆。主管忙碌或等待人类回答时，新委托会被拒绝，不会插入另一段并行主管会话。

例如：

> 为这个项目建立评审工作室。让一个工位检查安装流程，另一个工位核对功能说明，各自在私聊中完成检查。把共同要求写到公告板，等两边交付后，再开群聊讨论分歧，汇总修改建议。

接续已有项目时，可以这样交代：

> 继续昨天的评审工作室。先查看各工位的近期事项和已有交付，需要时读取工位记忆，确认用词约定和待核实的问题。已完成的检查不用重做，把剩余问题交给对应工位，最后给我一份进展简报。

进入气旋后，可以查看这些工位的实际会话、群聊讨论和公告板，也可以直接接手其中的工作。

## 回看进展

工位私聊和群聊会显示回复、工具活动与工位联络。异步派工有自己的状态和结果记录；完成后，你可以查看结果，再决定是否把它带回群聊讨论。

工作台的最近事项和工位「履历」还会记录岗位配置、绑定 Agent 和工位记忆的变更。展开记录可以查看时间、来源及相关条目，并前往对应配置或记忆页面。这些变更不计入执行次数；完整提示词和记忆正文仍在原资料中查看。旧资料没有记录过的变更不会补造履历。

统筹 Agent 可以按工位分页查询履历，补读概况中未展示的事项。信息送达、主管已查看、工位执行完成和整个项目交付是不同状态，需要结合相应会话、派发结果与记录确认。

工位私聊、群聊、会议助理私聊和主管会话，都可以在各自输入框发送 `/compact`，整理后继续交流；发送 `/reset`，则归档并清空当前对话。清空主管会话也会结束此前目标的自动跟进，需要重新交代目标。

群聊中的 `/reset all` 会同时归档并清空公共讨论与会议助理私聊。群聊压缩需要先为工作室设置会议助理。
