# 总体架构

4torm 的界面承接人类操作，服务端运行 Agent、工具和协作任务，模型提供商负责生成回复。配置、会话与任务记录保存在本地。浏览器与 Electron 桌面端使用同一套功能区；桌面端还提供本地文件路径和执行视窗等能力。

## 一项工作如何流转

人类在季风、对流、气旋、信风或潮汐中发起工作。服务端结合当前场所的上下文、Agent 配置和可用能力调用模型；模型需要工具时，服务端执行工具并把结果交回。回复和执行变化可以实时显示，完成后的内容由所属功能区保存。

实时传输用于呈现正在发生的过程，不是历史记录本身。重新打开页面时，界面读取已保存的内容；支持活动同步的功能区还会查询仍在运行的任务。断线前只在屏幕上出现、尚未保存的片段不会重新播放。

## 功能区与中心路由

控制台中的 Agent 可以进入多个功能区，但各功能区拥有自己的会话、工作区和运行规则。一个场所的完整对话不会自动成为另一个场所的上下文。

人类界面、Agent 工具和定时调度有不同的入口。涉及功能区协作的操作经过中心路由检查和分发，再交给相应功能区决定如何执行。功能区通过公开接口协作，不直接依赖彼此的内部实现；中心也不保存第二份业务状态。

## 状态、记录与恢复

当前状态和历史记录以各功能区的实际执行与保存结果为准。它们通过统一的观察方式向界面和 Agent 提供需要的事实；无法读取的部分会明确表现为信息不完整，不能伪装成空闲或成功。

关闭浏览器标签页不等于服务端停止。由服务端独立托管的工作可以继续，而依赖当前流式连接的交互可能中断。桌面端关闭时会结束由它托管的服务端。正常退出时服务端会收尾；强制关闭或断电后，尚未保存的输出可能丢失。重新启动后，应以重新读取的状态和记录判断工作的结果。
