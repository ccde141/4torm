# 桌面化 · Electron

4torm 可以在浏览器中运行，也可以使用 Electron 桌面端。两种形态使用相同的界面与功能区，数据保存在所连接的后端。本机桌面模式额外提供本地文件路径和原生执行视窗能力。

## 启动桌面端

桌面开发模式：

```bash
npm run electron:dev
```

构建后运行桌面生产模式：

```bash
npm run build
npm run electron:prod
```

Linux 图形桌面的安装与启动见 [Linux 桌面版](https://github.com/ccde141/4torm/blob/master/LINUX.md)。把后端部署在 Linux 或 Docker、从其他设备连接的方式，见[独立后端与远程客户端](https://github.com/ccde141/4torm/blob/master/REMOTE.md)。

## 桌面端能力

本机桌面模式可以取得拖入文件的真实本地路径，使 Agent 能够按照当前工作区和执行权限访问文件。浏览器和远程桌面模式通过上传传送文件内容，不会把客户端磁盘路径当作后端工作区路径。

使用浏览器工具时，本机桌面模式可以在应用内显示原生浏览器视窗。用户可以从任务板打开视窗，在 Agent 与人类之间切换控制，并在需要时关闭执行。目前该能力用于季风会话和气旋普通工位私聊；远程客户端不提供本机执行视窗。

## 服务生命周期

本机桌面模式会启动并连接 4torm 服务端。关闭应用时，桌面端会结束由它托管的服务进程；关闭前应先等待重要任务和后台执行完成。

配置远程后端地址后，桌面端只连接该后端，不会启动本机服务。关闭远程客户端或浏览器页面，不会关闭独立部署的后端。

直接运行服务端时，服务端收到正常退出信号会执行排空流程。强制结束应用、直接关闭桌面端或系统断电时，尚未写入的运行状态可能丢失。需要保留重要运行数据时，仍应定期备份 `data/` 和项目外部工作区。

## 安全边界

桌面页面不会直接获得完整的 Node.js 能力。文件路径和原生执行视窗通过受限的桌面接口提供；Agent 的文件访问仍受其执行权限和当前工作区约束。

具体数据位置见[数据目录](./data-layout)，文件权限见[安全与隔离](./security)。
