# MCP · 外部工具接入

MCP 用于将外部工具服务接入 4torm，使 Agent 能够使用搜索、浏览器、数据库或其他应用提供的能力，而不需要为每项能力单独编写本地工具。

当前支持三种连接方式：

- **stdio**：由 4torm 启动本地 MCP Server 进程，并通过标准输入输出通信。
- **Streamable HTTP**：连接现代 MCP Server 提供的远程 HTTP 地址。
- **SSE**：兼容仍使用 SSE 传输的旧式远程 MCP Server。

4torm 当前接入 MCP Server 提供的工具，不处理 MCP Resources 和 Prompts。远程服务可以通过自定义请求头使用固定 Token 或 API Key，但暂不处理 OAuth 登录流程。

MCP Server 连接成功后，其工具不会自动提供给所有 Agent，需要进入 Agent 配置页面，选择该服务中的全部工具或单独选择需要的工具。Agent 调用时与本地工具没有区别，但实际能力、数据访问范围和运行结果由对应的 MCP Server 决定。

## 添加 MCP Server

在侧栏「能力」分组中打开「MCP」，点击「添加」，选择连接方式并填写服务配置。

服务名称用于页面识别和 Agent 工具分组，创建后不能修改。

使用 **stdio** 连接本地服务时，需要填写启动命令，并按顺序逐项添加启动参数；每一项都是一个完整参数，其中的空格会被保留，还可以按需设置环境变量和工作目录。

使用 **Streamable HTTP** 或 **SSE** 连接远程服务时，需要填写服务 URL。远程服务要求固定 Token、API Key 或其他请求头时，可以在请求头区域逐项添加。

已有 MCP 配置也可以通过 JSON 导入。系统支持单项配置，以及使用 `mcpServers` 包装的多项配置；批量导入时，只有全部配置均有效且名称不冲突才会保存。

保存后，服务默认启用并立即尝试连接。连接成功后，卡片会显示发现的工具数量；连接失败时会保留配置并显示错误。已启用的服务会在约一分钟一次的健康检查中尝试恢复，也可以在修正配置后手动重新连接。恢复连接不会重放之前的工具调用。

## 管理 MCP Server

![MCP Server 管理页面](/images/extend/mcp-server-current.png)

每张服务卡片会显示连接方式、启动命令或服务地址，以及当前连接状态；连接成功时会显示已经发现的工具数量，服务未启用或连接失败时，相关工具不会提供给 Agent。

关闭服务开关会断开当前连接，但保留服务配置和 Agent 已有的工具选择；再次启用时，系统会重新建立连接并读取工具列表。

点击「编辑」可以修改连接方式及其配置，服务名称保持不变；保存后，已启用的服务会使用新配置重新连接。

「重连全部」会重新连接所有已启用的服务。服务意外断开后，后台健康检查会尝试恢复；停用或删除的服务不会恢复。对于有绑定窗口等内部状态的服务，恢复连接后应重新确认状态，不能重复执行结果不明的操作。

删除服务会移除其配置并断开连接，相关工具也会立即变为不可用。

## 为 Agent 选择 MCP 工具

MCP Server 连接成功后，进入控制台并打开 Agent 的配置页面，工具区域会按服务名称列出当前已经发现的 MCP 工具。

展开对应服务后，可以单独选择某项工具，也可以点击「全选」启用当前列出的全部工具。MCP 工具不会因为服务已经连接而自动加入 Agent；新建 Agent 和已有 Agent 都需要明确选择。

「全选」只作用于当前已经发现的工具；如果 MCP Server 之后增加了新工具，需要重新进入 Agent 配置并再次选择。

保存配置后，新的工具选择会从 Agent 下一次执行开始生效。服务暂时断开时，Agent 的选择仍会保留，但相关工具在重新连接前不可使用。

工具配置页可以通过「刷新 MCP 工具」重新读取列表；返回该页面或切回窗口时也会刷新。读取失败会明确显示错误，刷新不会替 Agent 选择新工具。服务使用分页工具列表时，4torm 会在完整读取后更新清单。

## 配置文件

MCP Server 配置保存在 `data/mcp/servers.json`。该文件已被 Git 忽略，因为环境变量和请求头中可能包含 Token 或 API Key；Git 忽略不等于备份，迁移本地环境时需要单独保留。

通常应通过 MCP 页面管理服务。开发者也可以直接编辑配置文件，运行中的 4torm 会重新读取变更。

```jsonc
[
  {
    "name": "local-tools",
    "enabled": true,
    "transport": "stdio",
    "command": "npx",
    "args": ["-y", "some-mcp-package"],
    "env": {},
    "cwd": "/path/to/server"
  },
  {
    "name": "remote-tools",
    "enabled": true,
    "transport": "streamable-http",
    "url": "https://example.com/mcp",
    "headers": {
      "Authorization": "Bearer YOUR_TOKEN"
    }
  }
]
```

SSE 服务使用与远程 HTTP 服务相同的 `url` 和 `headers` 配置，只需将 `transport` 改为 `sse`。

## 管理接口

MCP 页面通过以下接口管理服务，所有路径均以 `/api/mcp` 开头：

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET` | `/list` | 读取服务配置、连接状态和工具数量 |
| `POST` | `/add` | 添加并连接一个服务 |
| `POST` | `/update` | 更新已有服务的连接配置 |
| `POST` | `/import` | 批量导入已经解析的服务配置 |
| `POST` | `/remove` | 删除指定服务 |
| `POST` | `/toggle` | 启用或停用指定服务 |
| `POST` | `/reconnect` | 重连指定服务；不传名称时重连全部已启用服务 |
| `GET` | `/tools` | 按服务列出当前已经发现的工具 |

添加和更新接口使用“配置文件”一节中的服务结构。批量导入接口接收 `{ "configs": [...] }`；删除、启停和指定重连通过服务名称定位目标。

## 能力边界

4torm 控制的是某项 MCP 工具是否提供给 Agent，并不会替 MCP Server 限制其自身权限。工具能够访问哪些文件、账号或远程数据，取决于对应服务的配置；本地工具的工作区边界不会自动作用于 MCP Server。

MCP 工具参数保留 JSON 类型，包括数字、布尔值、数组和嵌套对象。文本与结构化结果会交给 Agent；图片通过独立的媒体引用传递，不会把 base64 当作正文。

模型的图片输入能力检测为支持时，下一次请求会携带工具返回的图片。每次工具结果最多保存 4 张，每张最多 8 MiB；每次模型请求最多发送最近 2 张工具图片，总计不超过 12 MiB。较早的图片保留历史引用，压缩不会删除原图。使用云端模型时，这些图片会发送给所选模型提供商。

图片能力未确认或不支持、图片无效、超出限制或文件读取失败时，工具结果会注明原因，其余文本与元数据仍保留。音频和其他二进制资源当前只提供说明，不作为模型输入；资源链接不会自动下载。媒体写入失败不会触发工具自动重跑。

工具记录会显示已保存图片的预览，可点击查看原图。图片读取使用相应会话或运行记录的归属信息；重新加载图片只读取已保存文件，不会重新执行截图或点击工具。前端显示了图片不代表模型已经看到图片，模型侧仍以图片能力检测和实际请求为准。

点击图片预览可查看原图，查看窗口右上角提供「在新标签页打开」和关闭按钮，也可按 Esc 退出。关闭图片后，可继续操作下层窗口。

图片无法读取时会显示原因，并提供「重新加载」按钮。若提示图片已被删除或移动，请先确认文件位置。

## 视觉桌面工具示例

通用链路是：**获取截图 → 模型根据图片选择动作 → 调用操作工具 → 返回新截图 → 模型检查结果**。这一循环直接使用已有 Agent 工具执行机制，不需要再建立一套桌面专用 Agent。MCP 服务负责实际操作，Skill 提供使用方法，4torm 负责工具授权、调度和图片传递。

例如，使用单独安装的 `vision-desktop` 项目时：

1. 在被控 Windows 的交互桌面中安装并自检服务。4torm 后端位于同一台 Windows 时，可以使用它的 stdio 启动配置；启动命令、参数及停止文件位置以该项目的安装结果为准。
2. 在 MCP 页面导入服务配置，确认能发现 `desktop_list_windows`、`desktop_bind`、`desktop_observe`、`desktop_act`、`desktop_status` 和 `desktop_stop` 六个工具。
3. 安装项目提供的通用 Skill。对于只有 Markdown 指南及相关资料的技能包，可以在 4torm 源码目录运行：

   ```sh
   npm run skill:install -- --source C:/tools/vision-desktop/skills/vision-desktop --data-dir ./data
   ```

   安装器生成 4torm 所需的技能元数据，保留原文，不覆盖同名技能，也不会安装桌面服务、自动执行脚本或授予 MCP 工具权限。附带执行器的技能包需要按[技能制作](./skills)单独接入。
4. 在 Agent 配置中启用该技能，并选择上述 MCP 工具；使用已经完成图片能力检测、支持视觉与工具调用的模型。技能中的短工具名对应实际列表中形如 `mcp:服务名称:desktop_observe` 的完整名称。
5. 从自己新建的练习窗口开始，先让模型读取截图中的可见内容，再尝试一次简单点击，核对操作后的新截图。仅连接成功、工具调用成功或人类看到了预览，都不能代替模型视觉与实际输入验收。

没有 MCP 的宿主也可以为同一执行层实现普通工具适配，但必须保留参数类型、图片结果、观察标识与错误语义。只复制 Skill 不会创建实际执行工具。能描述图片也不保证模型能准确定位坐标。

`vision-desktop` 当前提供 Windows 本地 stdio；Linux 或 Docker 后端不能直接借此控制 Windows 前端电脑，需要另行提供运行在目标 Windows 上的受控转发或执行端。对于只有一份窗口绑定和观察状态的服务实例，应只交给一个活跃控制会话；请求串行不等于跨会话状态隔离。连接丢失、超时或取消后，不自动重放点击，先重新观察确认结果。
